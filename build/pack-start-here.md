# Start with one useful result

If you run a business, pick one job from these guides. Use the steps to make one draft you can check. Start small, then add the tools the work needs.

**Choose a job → Share its guide and your files → Check one result**

1. Open one guide in `skills/`. Read what it needs, its steps, its checks, and who gets the result next. Start with work you understand, such as drafting a short article from your own call notes.
2. Give your AI app the guide and the source files it can read. You can attach the file or copy its text. A web link works only if that app can open it.
3. Copy the prompt below. Fill in your business, goal, files, and where the result should go. Have the app identify any missing file or account access before the step that needs it.
4. Open the result and check it against the guide. Save the output, source version, checks, and any unfinished work. A good answer alone does not prove an installed skill was selected.
5. If you want a reusable setup, follow our [current installation guide](https://localservicespotlight.com/install/). Check the package, enabled skill, fresh-task load, access, and result in your actual app.

If a guide calls for another file, script, or template, open that guide in the [Task Library](https://local-service-spotlight.github.io/task-library/). If it has a **Download full skill suite** link, use that download and keep its folders together. Ask your app to check that all required files are present before starting. If the full suite is not linked, use the guide's named source or keep the missing file as an unfinished step.

## For a job that repeats

A one-time draft does not need a schedule. If you want the work to repeat, agree on its trigger or time, time zone, owner, inputs, access, output location, and what happens on failure. Use the AI app's supported scheduling feature. Check the first actual run before relying on it. Saving a schedule does not prove it ran.

## What this download contains

This is a dated archive of guide files. The existing guide paths and manifest describe its contents. It is separate from the curated Local Service Spotlight plugin. The archive is not a universal app installer: downloading it does not connect accounts, load a skill, start a worker, or set a schedule.

In the catalog, `complete` is the contributor's claim that the guide is complete. It does not prove independent review, a real client result, installation, access, or scheduling. Some bundles also include guides marked `needs-work` or `gap`; read those limits before use. A missing example or unchecked step stays a gap.

This downloaded copy does not update itself. Get a newer release when you need newer instructions. Compare changes and keep the prior copy until you know you can recover any active work that relies on it.

## If you get stuck

- **The app cannot read the guide:** attach the Markdown file or copy its text. Ask it to name the guide before doing the task.
- **A file or account is missing:** supply that exact input or use the [access setup guide](https://localservicespotlight.com/install/). A guide does not grant access.
- **The installed skill is missing:** use the current setup steps for your particular app. Record the package and version, then check in a fresh task. These archive files are not a promise of a supported installation format.
- **No output arrived:** check the destination and the actual run history. Keep the error or unfinished state; a completed chat is not proof of delivery.
