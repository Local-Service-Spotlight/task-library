# How we use Listen Notes to find, track, and repurpose every podcast appearance

A search for your name can find old podcast visits. It can also find people who only mention you. This guide helps you tell the difference and save the useful results.

**The path:** Name query → Search matches → Episode proof → Merged inventory.

**Use this when:** The appearance inventory needs a reproducible Listen Notes discovery pass.

## Inputs
- Verified public name variants, known shows and identity context.
- The master inventory with lead/verified/mention/rejected/unresolved states.
- Listen Notes search access; exports and alerts may require existing paid access or separate purchase scope.
- Search date/filters and a named inventory owner.

## First-run prompt

> Search the supplied name variants on Listen Notes and record query/filter/date coverage. Capture accessible results or use the already-authorized export. Verify actual episode presence, merge duplicates and keep mentions separate. Treat scores and alerts as their actual measured states; do not buy access or invent delivered notifications.

## Steps
1. Prepare each quoted name variant and known show query. Record query, date and filters so another reviewer can repeat the pass.
2. Search Episodes and capture observed counts and accessible rows. Inspect Podcasts separately for hosted shows. A show match, episode match and verified appearance are different units.
3. Save title, show, date, Listen Notes URL, primary episode link and matching context. Export only when the actual feature/access and cost are in scope; otherwise capture the bounded results manually and state any uncollected remainder.
4. Use filters only when they fit the assignment and record them. Do not apply unique-podcast filtering if the goal is every episode, since that can hide multiple appearances on one show.
5. Open source show notes or episode evidence to verify identity and role. Listen Notes does not transcribe or search all audio; available transcript matches are a limited discovery source. A name in one is still only a mention until presence is established.
6. For priority verified rows, record any available Listen Score/percentile with its date as a show-level estimate. It does not prove guest presence, episode views, revenue or a comparable cross-platform rank.
7. Merge verified rows into the master inventory using episode identity and preserve all source links. Reconcile duplicates and review uncertain matches against Podchaser, YouTube or the host page.
8. If clipping is requested, use only a verified permitted source with actual start/end times and save the resulting state. Search completion does not require creating a clip or making a public playlist.
9. If monitoring is authorized and available, create or reuse the exact Listen Alert query, filters and email/RSS receiver. Verify the saved setting and first actual delivery; keep it “configured, first delivery pending” until observed. Return the updated inventory and remaining coverage gaps.

## Definition of done (QA checklist)

- [ ] Queries, filters, observed counts and captured rows are reproducible.
- [ ] Every confirmed row has primary role/identity evidence.
- [ ] Search/export/score counts are not substituted for verified appearances.
- [ ] Master merge and optional alert state are recorded without hidden purchase or delivery claims.
