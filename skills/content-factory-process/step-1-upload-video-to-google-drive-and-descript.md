# Step 1: Upload video to Google Drive and Descript

Your best video is hard to use if no one can find it. This guide puts the source and work copy where your team needs them. Start with the right file and the folder for this job.

**The path:** Source file → Safe archive → Descript work copy → Two checked links.

**Use this when:** A specific raw recording is ready for Process and a tracker row identifies the project.

## Inputs
- The original file, source date, real speaker names, permission to use it, and any access limits.
- The existing Content Library intake folder and tracker. Run [Set up the Content Library](https://local-service-spotlight.github.io/task-library/?task=set-up-content-library#task-set-up-content-library) if they do not yet exist.
- Write access to the exact Drive folder and Descript project/drive; enough permitted media minutes for this import. Check the actual account rather than requiring Enterprise by default.
- The agreed naming rule, priority, assigned editor, and intended next action.

## First-run prompt

> Use this source file and exact intake row. Check for an existing import, save the original in the approved archive, and prepare the matching Descript work project. Keep previews silent. Return both checked links, duration, access state and any remaining source review; do not mark an unfinished upload done.

## Steps
1. Read the queue and claim one unprocessed row. Follow any real priority; oldest first is a fallback queue rule. Check that another worker has not already imported it.
2. Inspect the source name, format, duration and completeness. Review accessible frames/captions with silent controls. If intelligible speech has not been checked by an authorized reviewer or non-speaker audio analysis, record that pending check; metadata cannot prove it.
3. Keep the original file intact. Use the existing naming convention, such as YYYY-MM-DD-topic-person, on the working copy or archive entry. Record the original filename so the source can still be traced.
4. Check whether the exact file is already in the brand’s 01-Raw folder. If not, upload through Drive’s New/File upload or the supported project route and wait until complete. Compare duration/size and open the stored item.
5. Check archive ownership and access. In My Drive, placing a file in someone else’s folder does not transfer ownership; a shared drive belongs to the organization. Use the project’s actual approved arrangement without broadening sharing.
6. In the correct Descript drive, create or reuse the matching project and import this same source. Wait for the Activity panel to finish. Add the media to the script when transcription/editing is needed; a file merely listed in the project is not a finished composition.
7. Check the composition contains the expected complete duration and visible frames. Keep a source version before later cuts. Verify that the intended next editor can access both the archive and work project.
8. Save both exact links, file identity, import state and any unresolved speech check in the tracker. Mark this intake as picked up once, then hand the record to transcription.

## Definition of done (QA checklist)

- [ ] The complete source is in the intended archive with actual ownership/access known.
- [ ] The matching Descript work project contains the intended media and has finished importing.
- [ ] Both links, original identity, duration and next editor are recorded once.
- [ ] Playback or speech checks are evidenced or explicitly pending; no silent test is called an audio pass.

## Example(s)

**Fictional teaching example — no file was uploaded.** Maple Cycle has a six-minute clip named `phone_042.mp4`. Its intake row calls it “What to bring for a repair quote.” The editor keeps that original and names the archive entry `2026-09-01-repair-quote-alex`.

The row records a six-minute Drive file and a six-minute Descript composition. The file sits in the shop’s shared drive, so the ownership note says “organization shared drive,” not “folder owner owns every uploaded file.” If Descript still shows an import in progress, the row says “archive ready; import pending.” The transcription handoff begins only with the actual completed project.

## When this runs

Once for each new source or a specifically requested replacement. Use the existing queue trigger only if configured; no automatic upload sweep is installed by this guide.

## First-run setup and continuity

Open the supplied task file and its linked source. Verify the project’s real inputs, account, access and output folder before work. This Markdown file is a guide; it does not install an app, connect an account, supply a subscription or create a schedule. Carry out work already authorized; do not ask for the same approval again. Keep any unsupplied destination or new action outside that scope clearly pending.

Save source IDs, versions, decisions, checked outputs and next owner in the project tracker. Before a retry, check the saved state and other workers’ changes. A model name does not guarantee memory or a running timer. Repeated work needs an actual configured trigger and durable state; one-off work can be started by the prompt above.

Keep agent media muted with volume zero before playback. If mute cannot be verified, use captions, metadata or still frames. State the limit: silent visual checks do not prove spoken-word accuracy or audio quality. Do not start sound through the user’s speakers unless explicitly asked.
