# Maintain a canonical honor and story leaves

**Use this when:** New source material honors a real relationship and must feed one existing or justified canonical honor page.

This is a registered recipe in review. A published guide or this new record does not certify its runtime behavior. Read the current [canonical procedure](https://blitzmetrics.com/one-canonical-honor/) before executing; it contains the detailed actions and current source-specific instructions.

## Inputs
- Verified relationship and intended GCT
- Real recording and full transcript
- Existing hub and story leaves
- Approved distribution destinations

## Prerequisite tasks
- No separate mandatory task is established by the reviewed source; use the explicit starting condition and inputs above.
## Input references
- [#GCT: Business Strategy](https://blitzmetrics.com/gct-business-strategy/)
- [The SEO Tree Framework: How Every Piece of Content Should Connect](https://blitzmetrics.com/seo-tree/)
## Steps
1. Inventory the source material.
2. Process each tape into its own sourced story.
3. Place the story on the tree and link the honor hub.
4. Update the hub and the entity-home relationship.
5. Promote only through the approved distribution path.

## Definition of done (QA checklist)

**Expected result:** One canonical honor page with connected story leaves and a source-backed inventory.

- [ ] No competing honor master is created
- [ ] Each leaf names and links its actual branch
- [ ] The hub links the real entity home
- [ ] Embeds use verified IDs and caption parameters
- [ ] Anonymous public verification confirms the current content
- [ ] Record the exact source revision, actual result and evidence; retain failure, partial, blocked and unknown states.
- [ ] Write the execution's meta article and link the canonical task. Publication is a separate action under the current authority.
- [ ] Keep this parent job's internal retries, checks and agent contributions on the same execution ID; derivatives and revisions add no runs. A separately scoped and documented child execution may have its own ID with parentExecutionId, without adding a second completion to this parent recipe.
- [ ] Verify permissions for publishing, sending, spending, scheduling or changing access before that action. A task record does not grant them.
