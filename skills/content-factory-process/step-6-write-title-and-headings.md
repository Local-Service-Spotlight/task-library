# Step 6: Write title and headings

A clear title helps the right reader choose your page. Good section names help them find the answer. Start with what the article really teaches, then name that promise in plain words.

**The path:** Real article promise → Clear title → Useful headings → Checked search preview.

**Use this when:** The article body is drafted and needs its visible title, section headings and search description.

## Inputs
- The full draft, [Goals, Content, and Targeting](https://blitzmetrics.com/gct-business-strategy/) brief and reader’s main question.
- The current site title convention, existing URL/title if updating, and intended author voice.
- The actual WordPress/template title behavior and search-preview tool when available; a character counter is only an editing aid.

## First-run prompt

> Write a truthful title, search description and heading map from this full article and GCT. Use the reader’s words naturally. Treat 60/160 as optional house drafting targets, not Google limits. Check heading promises and the existing template before adding an H1; keep the current canonical URL.

## Steps
1. Read the article and write one sentence stating what it delivers. Reject title options that promise results, speed or certainty the source cannot support.
2. Draft a clear visible title using the reader’s natural words. Keep it concise and distinct from other pages on the site. Do not rename an established URL just because the title improves.
3. Write a search-title version only when the site uses a separate field. The old under-60 rule can serve as a house drafting target, but Google has no fixed title character limit and may choose different title text. Judge the actual preview and meaning.
4. Write a concise meta description that explains the useful answer. The old under-160 target is not a Google limit or a guarantee of what appears; Google may use the page’s own text. Avoid unsupported offers or results.
5. Make each H2 describe the section’s real answer. Use H3 for a true subtopic under that H2. Use natural variants of the question where helpful, without a quota of keywords in headings.
6. Check the visible page structure: one clear article H1 under the site’s publishing standard, logical H2/H3 nesting, and no fake headings made only by bold text. Existing templates can supply the H1, so avoid duplicating it in the body.
7. Read the headings alone like a contents list. Check that each promise is fulfilled in its section and the order makes sense. Preserve useful source-specific detail without clickbait.
8. Save visible title, optional SEO title, description and final heading outline in named fields. Pass them to the hook writer and later search-metadata task with any template preview check still pending.

## Definition of done (QA checklist)

- [ ] Title and description accurately represent the article without unproved promises.
- [ ] Headings make a clear, logical map of actual section content.
- [ ] Visible H1 and template behavior are checked or specifically pending.
- [ ] Preview length is treated as a display/editing concern, not a Google ranking requirement.

## Example(s)

**Fictional teaching example — no page was changed.** For the sample photo checklist, use the title “What photos help with a bike repair quote?” The headings are “Show the whole bike,” “Show the issue up close,” and “Explain when it happens.”

A matching description is: “See which bike photos and notes help a shop prepare for your visit, and why a final quote may still need an inspection.”

“Exact bike repair prices in five minutes” is rejected because the article cannot deliver that promise. If the template already prints the page title as H1, the article body begins its sections at H2.
