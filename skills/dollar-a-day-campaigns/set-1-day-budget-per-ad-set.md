# Set $1/day budget per ad set

A small ad test needs a clear price. This guide helps you set a starting budget and check the total cost. Start with the number of tests and the date each one must end.

**The path:** Test rows → real budget controls → total commitment → saved limits.

**Use this when:** The approved content and audience plan is ready to be priced and configured for a small test.

## Inputs
- The exact test rows, goal, dates and planned number of active tests.
- Account currency, time zone, current minimums and available budget/limit controls; access for the planned configuration.
- The billing owner, authorized total, any fees and existing campaign commitments; due review and stop authority.

## First-run prompt

> Price this test matrix using the actual account’s budget controls. Use $1/day for seven days only where supported, show the full commitment, and distinguish averages from caps. Re-read any authorized saved settings. Leave a plan that exceeds the supplied amount pending instead of silently raising it.

## Steps
1. Confirm the goal and qualified source content before funding anything. The method starts with a small paid test of proven work; small spend still has a real cost and does not guarantee useful sample size.
2. Map the actual budget level. In a Meta setup with ad-set budgets, a row can use that control; a pooled campaign budget may allocate differently. Google Ads budgets belong to campaigns, not ad groups. Do not force the task’s historical title onto every platform.
3. Read the account’s accepted minimum, currency, billing terms and objective-specific settings. Try the nominal $1/day only if supported within scope. If a platform requires more, show the true amount or choose fewer tests through the existing decision process; do not relabel $20 as one dollar.
4. Choose a supported daily or total/lifetime plan appropriate to the ceiling. A daily average can vary by day. For a hard total, verify the actual total/limit control and dates; an informal reminder is not a platform-enforced cap.
5. Calculate every commitment, including overlapping old tests. At the nominal method amount, one seven-day test plans $7; five plan $35. Show currency and any separately applicable fees. The calculation is a plan, not a fabricated future charge.
6. Set the exact start/end dates and the due review before an authorized activation. Record what happens at expiry and who can pause. A calendar entry alone does not prove an automatic stop exists.
7. Re-read all saved budgets, limits and dates by ID. If the chosen campaign mode pools spend, preserve that fact in the log. A successful save is distinct from policy approval and actual delivery.
8. Check spend and delivery early within the existing scope, then review the full planned window. Avoid unnecessary mid-test changes, but do not ignore a wrong amount, broken destination or other agreed protective-stop condition.

## Definition of done (QA checklist)

- [ ] Real budget level, minimum, currency and pacing are documented.
- [ ] Nominal daily math is not confused with a hard total cap.
- [ ] All overlapping commitments fit the actual authorized envelope.
- [ ] Saved limits, dates and expiry behavior are read back.
- [ ] The due reviewer and early protective checks are real, not model promises.

## Example(s)

**Fictional teaching example:** Five eligible seven-day tests at a nominal $1/day plan $35 in total. Two start Monday and three start Wednesday, so their end dates differ. The operator records the platform’s actual spend controls and any fees before activation. If only $21 is authorized, the five-row plan does not pass: three rows may fit after scope is reconciled. The guide does not call $35 “zero risk,” and it does not promise that typing a daily amount creates a hard weekly cap.
