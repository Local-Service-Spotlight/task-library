# Kill underperforming ads

An ad can spend money without doing the job you gave it. This guide helps you stop weak tests and keep a clear record. Start with the goal, the test dates and the actual cost.

**The path:** Due test → checked rule → exact pause → saved lesson.

**Use this when:** A test reaches its decision date, or an active ad violates an already agreed safety or spending rule.

## Inputs
- Exact account/ad-set/ad IDs, current status, full-window report and target from the test plan.
- The pause/stop authority already granted, any early-stop rule, remaining budget and other workers’ current actions.
- A dated test log with the original creative, audience, changes, output evidence and next owner.

## First-run prompt

> Review these due ads against their agreed targets and stop rules. Name the exact records to pause and why. Apply only the pauses already authorized, re-read the status, and keep all history. Report recommendations separately if action authority or evidence is missing.

## Steps
1. Match each due row to the exact account and object ID. Check whether another worker already paused it or a current plan replaced the old instruction. Do not act from a similar display name alone.
2. Confirm the reporting window, goal, result definition and tracking state. Separate poor measured performance from an absent or broken measurement. Use the original target, not a threshold chosen to make the desired verdict fit.
3. At the planned seven-day review, stop ads that fail the agreed rule. The method often retires about 90% across a portfolio; this is not a requirement to force nine losses from ten or remove a qualifying winner to meet a quota.
4. Act sooner on wrong destinations, unauthorized delivery/spend or other agreed safety conditions. Record the early-stop reason and partial window. A seven-day test is not permission to ignore a harmful error.
5. Pause the exact relevant ad or ad set within authority, preserving historical records. Check the campaign hierarchy so a broader pause does not stop unrelated work. Do not delete the evidence or silently replace the creative mid-test.
6. Read back the saved effective status and timestamp. A reported pause and zero future delivery are separate observations; reports and billing may include activity from before the pause. Escalate a failed state change to the campaign owner without blindly repeating it.
7. Record spend, results, reason and one lesson. Unspent money remains uncommitted unless the existing scope authorizes a specific reallocation. A pause does not itself authorize a new test or larger winner budget.
8. Send qualified winners and unresolved tracking rows to their separate next tasks. End with a clear stop/keep/hold list and an owner for each unresolved row.

## Definition of done (QA checklist)

- [ ] Every pause is tied to an exact ID, rule and current authorization.
- [ ] Full-window verdicts and early protective stops are distinguished.
- [ ] Paused state is read back; failed changes remain open.
- [ ] Historical metrics and creative/audience records are retained.
- [ ] No forced failure quota, deletion or unauthorized budget reallocation is claimed.

## Example(s)

**Fictional teaching example:** Three tests finish their week. A costs $1.40 per useful visit against a $2 target. B costs $3.50. C has broken tracking. The operator is authorized to pause failed or unmeasurable tests at the end date. B and C are paused by ID, then read back. C is labeled unknown outcome, not proven bad content. A’s existing end date still applies. The $7 that might have funded a new B test is not automatically moved to A.

## When this runs

Run at each test’s agreed due date and whenever an existing stop rule triggers. An automatic pausing rule requires explicit configured scope, permissions, state and a verified trigger; this guide does not create one.
