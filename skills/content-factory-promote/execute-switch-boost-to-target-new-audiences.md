# Execute switch boost to target new audiences

A post has helped one group of people. You want to test whether it helps another group too. This guide helps you keep the post, cost and results clear as you try the next audience.

**The path:** Verified pair → new audience hypothesis → separate test → updated map.

**Use this when:** A Promote-stage post has a qualified result and an untested relevant audience is proposed.

## Inputs
- Original post/ad IDs, full-window result and cost target; the current audience/creative map.
- The proposed saved/custom audience definition, date, eligibility and actual service-area fit.
- Account roles, authorized new-test or replacement scope, total commitments, spend controls and start/end dates.

## First-run prompt

> Prepare the next audience test from this verified winning post. Preserve the original evidence and use the same eligible post where supported. Check whether this is an additional test or replacement, avoid duplicate launches, and act only within the supplied budget and action scope.

## Steps
1. Confirm the original pair met its stated goal with enough evidence for a new test. Keep its actual post, audience, metric, window and budget record available; a display name alone is not enough.
2. Read the proposed audience definition and source. A saved preset from the insights task is a hypothesis, not proof of future results. Check service-area fit, permissions and any suggestion/expansion behavior.
3. Choose a separate test by default when the plan is to preserve a still-running winner. If the authorized plan is a replacement, record the old stop and new start explicitly. Do not accidentally change the old audience and destroy the comparison record.
4. Use the existing post ID in a supported preview, preserving it where the platform allows. If a format or account requires a new creative, label that derivative and the comparison limit; do not promise social proof transfers everywhere.
5. Keep the creative and goal comparable while changing the planned audience variable. Use the method’s $1/day, seven-day idea only where accepted. Account for differing launch dates, overlap and auction delivery; it is not a randomized causal test.
6. Add old and new spending commitments before activation. Reconcile current worker state and existing ads so this Promote task and the related Dollar-a-Day task do not launch the same test twice.
7. Read back authorized saved/active settings, then check early delivery and budget safety. Keep the intended review window stable unless an agreed protective rule requires a change.
8. At the due date, compare the same cost and result definition with the baseline. Record keep, stop or bounded hold, update the audience/creative map, and name the next stage only when its conditions are met.

## Definition of done (QA checklist)

- [ ] The winning pair and new hypothesis are source-backed and identifiable.
- [ ] Original evidence is preserved; any derivative or replacement is explicit.
- [ ] Actual budget controls, all commitments and dates fit scope.
- [ ] No duplicate test is created by overlapping recipes or retries.
- [ ] The updated map records the full result and its uncertainty.
