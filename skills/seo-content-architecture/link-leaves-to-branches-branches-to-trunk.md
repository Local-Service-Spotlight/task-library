# Link leaves to branches, branches to trunk

Link each story to the guide or service it helps prove. This task adds useful links between those pages. Start with the site map and the page each story helps prove.

**The path:** Checked parent map → Contextual upward links → Useful evidence links back → Link QA

**Start when:** The current content map names the owning topic and real offer destinations for the selected supporting pages.

## Inputs

- [Map actual content roles](https://local-service-spotlight.github.io/task-library/?task=map-content-hierarchically-root-trunk-branches-leaves#task-map-content-hierarchically-root-trunk-branches-leaves) with current entity home, actual topic/offer branches and supporting pages.
- [Choose the right entity destination](https://local-service-spotlight.github.io/task-library/?task=follow-entity-linking-decision-tree#task-follow-entity-linking-decision-tree) and the selected pages’ [Goals, Content, Targeting: the result, source material and people served](https://blitzmetrics.com/gct-business-strategy/) briefs, source revisions and publication scope.
- The specific source-to-target link plan, existing useful links and known destination status.

## Steps

1. Read the selected page and its mapped parent before editing. State the connection in the reader’s terms: what the story shows and which method or offer helps next. Reject a mapped relationship that exists only because of a shared keyword; update the map with the actual finding.
2. Add a contextual link from the supporting story or execution record to the canonical method it uses. Where it genuinely helps, connect relevant proof to the real service or buying page and practical how-to. Keep the story’s unique evidence rather than replacing it with a copy of the whole method.
3. On the owning method or topic page, make the entity home and relevant offer path understandable. Use the current Directory convention: the home is the trunk and off-site proof supplies roots. Do not invent another homepage/root URL or chain every reader through an unnecessary layer.
4. Add relevant cross-links where one method actually depends on or explains another. The tree is a useful primary hierarchy, not a ban on lateral paths. Check prerequisites and downstream actions by their actual task contracts; neighboring catalog entries are not automatically real dependencies.
5. Link the hub back to useful verified examples with a sentence or two explaining what each shows. A case or meta article can both support its hub and be discoverable from it. Prioritize relevant credible evidence; a historical example remains dated proof and does not establish a new counted execution.
6. Review names and anchor phrases with [entity linking, choosing the right home for a named person or topic](https://blitzmetrics.com/entity-linking/). Natural descriptive body links are the work here; useful navigation remains valid. A two-word entity name need not be padded to meet a word count, and repeating the same link several times does not add distinct supporting posts.
7. After authorized release, check the actual normal pages and destinations, then save the link log and map changes. Record any missing parent, broken target or inaccessible source for the right owner. Pass the observed change set to QA and measurement without promising a ranking or conversion lift.

## Definition of done (QA checklist)

Quality assurance (QA) means checking the actual result against its agreed requirements. Follow the [Article Guidelines](https://localservicespotlight.com/article-guidelines/).

- [ ] Each upward link follows a meaningful relationship and reaches the verified owning destination.
- [ ] The tree’s labels and useful cross-links are accurate; no duplicate home node or artificial one-way-only rule is imposed.
- [ ] Evidence links back to supporting pages are useful and specific, with current public readbacks.
- [ ] The exact output, source revision, reviewer evidence and remaining owner action are saved.
- [ ] For any reader-facing output, the short grade-five opening states the reader’s useful outcome and supporting method or proof. The body delivers that promise; a useful authentic visual appears in the first screen. Retain exact text and quoted reviewer evidence.

## Example(s)

**Fictional teaching example. This is not a client result or proof of a completed run.**

A fictional course has a main method guide and a dated student exercise. The exercise links to the guide for the full method; the guide links back with a note about what the exercise demonstrates. A relevant course page remains the buying path. This two-way connection is useful navigation, not a reason to duplicate the guide in the exercise.
