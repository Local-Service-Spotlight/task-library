# Publish an SEO Tree site directory

Help readers see what your site covers and where to go next. This guide builds a linked map of your real pages and proof. Start with your checked page list and the home page that names the person or business.

**The path:** Checked hierarchy → Clickable map + text list → Source and visual checks → Public directory

**Start when:** The site’s checked hierarchy is ready for a public directory on its own domain.

## Inputs

- [Map actual content roles](https://local-service-spotlight.github.io/task-library/?task=map-content-hierarchically-root-trunk-branches-leaves#task-map-content-hierarchically-root-trunk-branches-leaves) with actual URL roles, entity home, topic/offer branches and supporting pages.
- Current source/builder, any existing directory URL, approved publishing scope and public-safe identity evidence.
- The [SEO Tree, the map that links a site’s proof to its main topics and offers](https://blitzmetrics.com/seo-tree-site-directory/) method, current [Article Guidelines](https://localservicespotlight.com/article-guidelines/) and real node/label data rather than decorative example leaves.

## Steps

1. Inspect the existing site directory and the source that owns it. Improve the current canonical route where it already serves this job. Choose a new directory path only when needed and agreed; do not rename a live method article or change the site’s routing just to force a preferred slug.
2. Use the verified entity home as trunk, actual major topics and offers as branches, and relevant existing content as leaves. Identify off-site roots from genuine identity or proof sources. An appearance, a profile and praise are distinct evidence types; the map must not imply endorsements that those sources do not contain.
3. Check each selected branch against the current site’s own navigation and content. Link its actual owning URL and describe what a visitor can learn or do there. Keep task recipes separate from topic hubs and historical stories. Missing or duplicate owners become explicit repair items before they are presented as resolved.
4. Build a useful clickable visual and matching visible text outline from the same data. Use clear groups, labels and real anchors that work with a keyboard. Show the actual scoped breadth; if the lead view is simplified, label its coverage and give a direct path to the complete directory.
5. Write a short grade-five opening that explains why this specific map helps the reader and how to use it. Put meaningful map content in the first desktop and mobile screen, followed by concise role explanations and real links. Preserve authentic relevant media and avoid a full-screen decorative title card.
6. Check every node’s destination, the text/visual agreement, public-safe source facts and the rendered page. Unknown destinations stay held or clearly labeled. Search-friendly markup can clarify visible facts but does not guarantee indexing, rankings or a search feature. Keep client metrics and private evidence out of public hidden data as well as visible copy.
7. Publish through the existing authorized source rail and verify the ordinary anonymous URL at the current required sizes. Save the source revision, date, checked links and remaining gaps. Use the directory for future page-placement decisions and send measured offer-link questions to the Money Tree task.

## Definition of done (QA checklist)

Quality assurance (QA) means checking the actual result against its agreed requirements. Follow the [Article Guidelines](https://localservicespotlight.com/article-guidelines/).

- [ ] The directory preserves its real source and route and represents the scoped published structure honestly.
- [ ] Clickable visual, text outline and actual destinations match, with meaningful first-screen content.
- [ ] Proof types and public/private boundaries remain truthful; normal public readback is recorded.
- [ ] The exact output, source revision, reviewer evidence and remaining owner action are saved.
- [ ] For any reader-facing output, the short grade-five opening states the reader’s useful outcome and supporting method or proof. The body delivers that promise; a useful authentic visual appears in the first screen. Retain exact text and quoted reviewer evidence.
