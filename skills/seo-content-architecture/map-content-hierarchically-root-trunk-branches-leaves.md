# Map content hierarchically (root → trunk → branches → leaves)

Give readers a clear path through the pages you already have. This guide maps your main topics, offers and the stories that support them. Start with the full page list and the real home of your business or name.

**The path:** Published inventory → Page roles and actual owners → Linked hierarchy → Gap decisions

**Start when:** A site needs its first content hierarchy or its existing map no longer matches the published pages.

## Inputs

- [Inventory pages and their purpose](https://local-service-spotlight.github.io/task-library/?task=step-1-inventory-content-and-establish-gct-per-page#task-step-1-inventory-content-and-establish-gct-per-page) with published URL/type/title, purpose, body links and current source.
- The real entity home, navigation, services, topic guides and public off-site identity evidence.
- The current [SEO Tree, the map that links a site’s proof to its main topics and offers](https://blitzmetrics.com/seo-tree-site-directory/) Directory convention and [Money Tree, a site map whose branch sizes show measured supporting links](https://blitzmetrics.com/money-tree/) count definition if a measured offer view is required.

## Steps

1. Reconcile every published URL in scope before grouping it. Use CMS/source inventory alongside the crawl so unlinked pages are visible. Mark planned, private, redirected, inaccessible and published pages distinctly; a blank in the export must not become an invented node.
2. Write the legend before drawing. In the current Directory and Money Tree views, the actual entity home/domain is the trunk and off-site identity proof forms roots. The older SEO Tree article also uses “root” for the homepage; label that viewpoint if retained instead of inventing a second homepage or forcing incompatible labels.
3. Identify existing topic/method hubs and buying/service pages from their real purpose and the site’s navigation. The Money Tree can group branches into actual audience or offer limbs. Do not manufacture an ideal category structure or treat every topic hub as an executable task recipe.
4. Assign supporting stories, case studies and real execution records to their primary owning method or topic. Keep useful cross-links when a source supports more than one relevant idea. Preserve utility pages in a separate functional group; their valid job need not be a marketing branch.
5. Compare mapped roles with actual links and content. Flag missing incoming paths, possible duplicate intent, broken targets, unsupported claims and proof gaps as separate findings. Two same-topic URLs need a reader-intent review before consolidation; a sparse branch is a truthful finding, not permission to draw extra leaves.
6. Build a clickable map and matching linked text outline from that inventory. Name the scope and date; show planned or unresolved nodes separately from live ones. If thickness represents a number, use an explicit measured definition and reproducible data, otherwise use a simple unweighted diagram.
7. Review the map against the real home, services, menu and selected bodies with the owner. Correct labels and gaps, preserve the source and record next tasks. Pass the checked map to the Directory or Money Tree task; those tasks own their specific publication, measurement and public/private gates.

## Definition of done (QA checklist)

Quality assurance (QA) means checking the actual result against its agreed requirements. Follow the [Article Guidelines](https://localservicespotlight.com/article-guidelines/).

- [ ] The legend resolves root/trunk viewpoints without duplicate or invented home nodes.
- [ ] All in-scope published roles are represented, with real owners and useful cross-links.
- [ ] A diagram and text outline agree; any density, number or unknown state follows actual source data.
- [ ] The exact output, source revision, reviewer evidence and remaining owner action are saved.
- [ ] For any reader-facing output, the short grade-five opening states the reader’s useful outcome and supporting method or proof. The body delivers that promise; a useful authentic visual appears in the first screen. Retain exact text and quoted reviewer evidence.

## Example(s)

**Fictional teaching example. This is not a client result or proof of a completed run.**

A fictional consultant has a home page, two services, one method guide and six stories. The map uses the home once as trunk, the real pages as branches, and the stories as supporting leaves. A LinkedIn identity page sits among the roots. A planned course is labeled planned, so readers do not mistake it for a live offer.
