# Add consistent headshots and bios across profiles

Help people know they have found the right you. This guide brings your photos and key facts into line across your work profiles. Start with your best current photo and the facts on your own site.

**The path:** Approved photo + facts → Platform drafts → Checked profiles → Identity map

**Start when:** The agreed public profiles exist, but their photos or bio facts differ.

## Inputs

- [Set up the agreed public profiles](https://local-service-spotlight.github.io/task-library/?task=set-up-professional-social-profiles#task-set-up-professional-social-profiles) with exact URLs and actual edit rights.
- An approved real headshot, crop files and permission for each use; the person’s accepted public name and verified current bio facts.
- The current site About page, allowed public contact details and a list of platforms in this pass.

## Steps

1. Compare the profiles with the site before editing. List wrong-person matches, outdated roles, old photos, broken links and missing access. Distinguish a genuine fact conflict from a platform’s length limit or a valid historic credit.
2. Choose a current real headshot that is clear at avatar size. Make the required crops from that photo and retain the original. Preview each crop so the face is recognizable; do not alter the person’s identity or create a fake event photo.
3. Write one-line, short and longer bios from the same verified facts. State the person’s work, the people served and relevant proof. Keep approved professional name and role consistent; a legal-name variant in an old record is evidence to reconcile, not erase.
4. Prepare the fields for each agreed profile. Use first person on the person’s site and the platform’s appropriate voice elsewhere. Follow [Article Guidelines](https://localservicespotlight.com/article-guidelines/) for reader value, real proof and natural voice; do not copy an unsupported credential into every bio.
5. Apply the approved edits through each platform’s supported control when authorized. Keep before values for recovery. External publisher profiles receive a specific correction request under the existing send authority; record any pending owner action instead of claiming it fixed.
6. Open the saved public profiles and compare name, photo, role and website link with the approved set. A blocked automated fetch requires a supported visible check or an unknown result, not automatic proof that the profile is correct.
7. Save the final URL list, checked facts, crop references and remaining gaps in the existing identity record. Recheck when roles or photos change; a quarterly review is a proposed cadence until the actual owner and schedule are recorded.

Quality assurance (QA) means checking the actual result against its agreed requirements. Follow the [Article Guidelines](https://localservicespotlight.com/article-guidelines/).

- [ ] The next owner receives the same bio set and checked profile list.
