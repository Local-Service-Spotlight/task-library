# Update a client Success Tracker

Keep the client’s work and results easy to find. This guide helps your team show what changed and who owns the next step. Start with the latest report and proof of what was done.

**The path:** Run evidence → Current tracker → Owned actions → Client review

**Start when:** A client’s current work and weekly evidence need to be prepared for its next review.

## Inputs

- [Write the agreed weekly report](https://local-service-spotlight.github.io/task-library/?task=submit-weekly-maa-report-every-friday#task-submit-weekly-maa-report-every-friday) and [Collect verified weekly measurements](https://local-service-spotlight.github.io/task-library/?task=collect-verified-weekly-measurements#task-collect-verified-weekly-measurements) outputs for the agreed period.
- The existing client Success Tracker or linked template, dated work artifacts, decisions, blockers and next actions.
- [The Success Tracker method](https://localservicespotlight.com/the-success-tracker-how-ai-apprentices-managing-local-service-clients-stay-organized-and-prove-results/) and verified destination/owner/access.

## Steps

1. Find the existing relationship tracker before creating a new copy. Read the current project overview and responsible lead so the record goes to the right people and does not fork an active source.
2. Gather the period’s dated artifacts and report. For each item distinguish planned, drafted, saved, published, delivered and verified states; link the evidence that supports the chosen label.
3. Update only relevant current sections of the actual template: strategic context, plumbing, goals, content, targeting and results as applicable. Preserve prior reports as dated history, and mark a missing source rather than leaving a misleading empty slide.
4. Add sourced metrics with definitions, period and comparison. Keep audience, engagement and business conversion outcomes distinct, including qualified leads, bookings and collected revenue.
5. Explain material changes and blockers in plain language. For each next action name one actual owner, due date or trigger, source need and acceptance condition. Resolve ownership from the authoritative project record instead of inventing a contact.
6. Preserve authority boundaries: the Client Roster owns relationship status; Client Tracker owns money/routing; verified project records own work destinations; measurement sources own metric truth. This tracker is the discussion and evidence view, not a competing control system.
7. Review dates, links, current screenshots, access and privacy. Save and reopen the exact tracker, then use it in the authorized team/client review. Record pending delivery or meeting as pending; merely updating the document does not prove the review happened.

## Start with an agent

Give the AI worker this recipe, the real Inputs, the desired result and the actions already authorized. Ask for the saved output, source evidence, passed and failed checks, and the next owner. A skill is a set of instructions. Loading it does not prove access, install a scheduled job or complete the work. Use the [current installation guide](https://localservicespotlight.com/install/) only if reusable setup is needed; a ZIP contains instructions and is not an access grant.

Use the actual supported app and verified source access. A model name is not a promise of browser control, memory or unattended work. For recurring work, inspect the real job’s trigger, owner, timezone and observed firing; this recipe creates no schedule. Before any media playback, mute the player and set volume to zero. A silent review does not prove sound was heard.
