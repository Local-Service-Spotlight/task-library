# Personal Efficiency (Do, Delegate, Delete)

Clear the next step for work that lands in your inbox. This guide helps you do it, hand it to the right person or set it aside with a clear reason. Start with one inbox and your current goals.

**The path:** Incoming item → Do / Delegate / Delete → Evidence → Follow-up

**Start when:** An agreed inbox or task list needs triage into clear owned actions.

## Inputs

- The exact inbox or task list in scope, with the operator’s current priorities and authority.
- Existing assignments, threads, deadlines and follow-up records.
- A suitable receiving owner where delegation is possible; relevant task guides.

## Steps

1. Define the source’s three choices. Do means own the action; Delegate means give a bounded task to a capable owner; Delete means decline, archive or remove only as appropriate and authorized. It does not require irreversible deletion.
2. Read each exact item and its history before acting. Check whether it already has an owner, sent reply or working follow-up so triage does not duplicate a live task.
3. Do a short in-scope action when the inputs and authority are present. For a longer action, record its next step, owner and due date in the existing task system. A calendar-bound task can be owned without being done now.
4. Delegate with the goal, sources, expected output, deadline and relevant guide. Preserve the originating thread and confirm the receiving owner’s acceptance where required. Do not send messages or grant access without the current authority.
5. Archive or decline irrelevant items under the source’s retention and communication rules. Keep records that support an active matter; do not unsubscribe, delete or refuse a commitment merely to reach zero.
6. Reconcile every in-scope item to a real disposition. Waiting on someone remains waiting with a next check; unread or inaccessible items remain unresolved. Inbox zero is a useful working view, not a reason to conceal open work.
7. Save the triage result and verified actions. Use any existing follow-up cadence; create a new schedule only when separately authorized. Compare useful completed outcomes and rework, not just the fraction delegated.

## Definition of done (QA checklist)

Quality assurance (QA) means checking the result against its agreed requirements; see the [Article Guidelines](https://localservicespotlight.com/article-guidelines/).

- [ ] Every reviewed item has a supported disposition and an exact next action if open.
- [ ] No duplicate handoff, unsupported send, irreversible removal or lost active evidence occurred.
- [ ] Waiting and blocked work remain tracked; completion reflects actual action.

Give the AI worker this recipe, the real Inputs, the desired result and the actions already authorized. Ask for the saved output, source evidence, passed and failed checks, and the next owner. A skill is a set of instructions. Loading it does not prove access, install a scheduled job or complete the work.
