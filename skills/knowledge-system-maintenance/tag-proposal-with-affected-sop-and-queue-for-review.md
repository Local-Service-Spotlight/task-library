# Tag proposal with affected task guide and queue for review

A good fix is easy to miss if it reaches the wrong list. This guide puts each proposal where its reviewer can find it. Start with the saved proposal and the guide it would change.

**The path:** Saved proposal → Format check → Exact guide tag → Reviewer queue

**Start when:** A saved process-change proposal needs a format check, exact guide tag and reviewer queue.

## Inputs

- [Draft a process-change proposal](https://local-service-spotlight.github.io/task-library/?task=create-sop-amendment-proposal-500-words#task-create-sop-amendment-proposal-500-words) output and the affected guide’s current canonical identity.
- The maintained proposal queue and a named reviewer with access.
- Submission source/time, priority and authority to update that queue.

## Steps

1. Read the whole proposal and count its body. Verify the four required parts and two real examples within 500 words; return gaps with a clear reason.
2. Tag the exact affected guide and section, keeping its canonical URL/source revision. A nickname or a similarly named article is not the correct target.
3. Check for an existing proposal about the same issue. Link related records or update the correct version without erasing the first submission time.
4. Add submitter, submission date, priority and current state. Split unrelated changes to different guides into linked proposals so each decision has a clear scope.
5. Place it in the approved review queue, ordered by genuine urgency then age. Record awaiting evidence or returned states honestly rather than calling every item ready.
6. Confirm the intended reviewer can read it and its private proof. Send any required notice only through existing authority. Keep the proposal queued until a real decision is recorded.

## Definition of done (QA checklist)

[Quality assurance (QA)](https://localservicespotlight.com/article-guidelines/) means checking the work against the agreed result.

- [ ] Format/target checks are recorded; missing evidence is explicit.
- [ ] No duplicate proposal or overwritten history is introduced.
- [ ] Reviewer can reach the item and proof; actual state and date are accurate.
