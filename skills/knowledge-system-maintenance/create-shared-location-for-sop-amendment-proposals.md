# Create shared location for task guide Amendment Proposals

Good fixes get lost when they stay in chat. This guide gives your team one place to propose a change and see its answer. Start by checking whether a shared queue already exists.

**The path:** Current queue → Format and roles → Test proposal → Tracking handoff

**Start when:** The approved process needs one findable proposal queue, or the existing one needs repair.

## Inputs

- The approved team workspace, current proposal locations and their owners.
- The [knowledge maintenance method](https://blitzmetrics.com/knowledge-system-maintenance/) proposal format: problem, affected guide, exact new wording and at least two real examples, within 500 words.
- Named submitters/reviewers and authority for any storage or access change.

## Steps

1. Find the maintained proposal home before creating one. The source allows a document, a WordPress draft or a project board; choose the approved tool that the intended users can reach.
2. Organize three clear areas: format/help, pending queue, resolved archive. Keep existing IDs, decisions and evidence links; do not merge histories without checking provenance.
3. Map roles to needed actions: submit, read, review and resolve. Grant only approved access and keep confidential client examples in authorized storage.
4. Seed the blank four-part format and one clearly labeled teaching example. A sample item uses a test ID and never counts as a real accepted amendment.
5. Have an intended submitter and reviewer perform a test handoff. Confirm they can find, read and resolve the sample with a reason. Use a test document for any simulated version/changelog update.
6. Link the canonical home from the maintained workflow under existing publishing authority. Prepare or send the exact notice only within the job’s communication scope.
7. Hand location, roles, test evidence and unresolved access to the tracking-system task.

## Definition of done (QA checklist)

[Quality assurance (QA)](https://localservicespotlight.com/article-guidelines/) means checking the work against the agreed result.

- [ ] One identified home contains format, queue and archive without losing prior records.
- [ ] Approved roles are verified by a submitter/reviewer test.
- [ ] Sample records are labeled and excluded from production amendment metrics.
