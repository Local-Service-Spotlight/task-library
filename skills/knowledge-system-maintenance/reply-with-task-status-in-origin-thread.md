# Reply with task status in the original thread

**Use this when:** Someone has asked you to act in a thread, or your status changes while they await the result.

This is a registered recipe in review. A published guide or this new record does not certify its runtime behavior. Read the current [canonical procedure](https://blitzmetrics.com/always-reply/) before executing; it contains the detailed actions and current source-specific instructions.

## Inputs
- The exact thread
- Actual work state and evidence
- Next owner and date or blocker

## Prerequisite tasks
- No separate mandatory task is established by the reviewed source; use the explicit starting condition and inputs above.
## Input references
- [Basecamp Basics – The Foundation of How We Work](https://localservicespotlight.com/basecamp-basics-the-foundation-of-how-we-work/)
## Steps
1. Return to the thread that asked.
2. Choose done, doing, blocked or parked.
3. Include evidence or the next date/needed owner.
4. Name coverage if you will be away.

## Definition of done (QA checklist)

**Expected result:** A useful status reply in the original thread within the standing twenty-four-hour rule.

- [ ] Done includes proof
- [ ] Doing includes a date
- [ ] Blocked names who or what is needed
- [ ] Parked names the living owner
- [ ] A separate-thread update is not counted as a reply
- [ ] Record the exact source revision, actual result and evidence; retain failure, partial, blocked and unknown states.
- [ ] Write the execution's meta article and link the canonical task. Publication is a separate action under the current authority.
