# Write Proper Title Tags and Meta Descriptions

Search results help people choose which page to open. This guide helps a site owner write clear titles and short page summaries. Start with the pages you want found and the question each one answers.

**The path:** Page intent → Clear title → Useful summary → Served check.

**Use this when:** new pages need metadata or existing intended-search pages have missing, misleading or unnecessarily duplicated metadata.

## Inputs
- The full in-scope intended-search page list, current titles/descriptions and canonical URL decisions.
- Each page’s actual purpose, reader and supported content, using the [Goals, Content, and Targeting](https://blitzmetrics.com/gct-business-strategy/) brief and owned SEO Tree.
- Access to the actual CMS, SEO plugin or template that controls the served title and description. Rank Math is not a prerequisite when another source already owns these fields.

## First-run prompt

> Review every page in the supplied scope and write truthful, useful metadata for its actual purpose. Treat length as a readability target, not a Google hard limit. Save through the owning source and compare the public result, keeping search-engine display choices separate.

## Steps
1. Inventory the intended indexable URLs and their served title and meta-description values. Separate missing or copied boilerplate from legitimate related pages, redirects and deliberate noindex content. State the page count so a sample is not mistaken for the full inventory.
2. Read each page and assign its distinct reader question or purpose in the SEO Tree. Related pages can share vocabulary without being duplicates; do not force a different keyword merely to make a spreadsheet unique.
3. Write a concise descriptive title that matches the page. Use the natural topic phrase where it helps and the brand where useful. The source’s roughly 60-character target is a house brevity aid, not a Google maximum or a reason to cut the meaning.
4. Write a clear meta description that summarizes the actual content and useful reason to visit. The roughly 160-character target is also a house aid. Avoid fake proof, unsupported promises or awkward repeated keywords.
5. For personal stories and evidence claims, preserve the source’s actual voice and relationship limits. Do not turn a co-appearance into an endorsement in a short title, or add a trophy-name list to attract clicks. Keep necessary material disclosures.
6. Save the fields in the real owning plugin or template without duplicating sources. Confirm that the existing template, builder or language variant does not override the specific page metadata.
7. Read every changed public URL and compare its title and description to the intended values. Check escaping, meaningful text, obvious duplicates and page-source ownership. Use a snippet preview as an approximation, not proof of a fixed Google display width.
8. If actual search results are observed, record query, date and shown text separately. Google can choose a different title link or snippet from page content. Save the page-to-purpose map and remaining issues; do not promise zero truncation across all queries and devices.

## Definition of done (QA checklist)

- [ ] All in-scope intended-search pages have a recorded metadata decision and coverage result.
- [ ] Titles and descriptions accurately describe their page and useful reader purpose.
- [ ] House length guidance improves clarity without false Google-limit or keyword-stuffing rules.
- [ ] Served fields match the intended source and no misleading duplicate boilerplate remains.
- [ ] Search observations are dated and distinguished from authored fields or previews.

## Example(s)

**Fictional teaching example.** A repair page’s old title is “Home | Best Service.” The lesson title becomes “Roof leak checks | Oak Repair,” and its summary says what a visitor can learn before asking for a check. A separate page explains emergency steps, so it keeps related roof wording but serves a different question. The useful result is two truthful page purposes with matching served fields, not a claim that Google must display them verbatim.
