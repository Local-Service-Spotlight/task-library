# Set Favicon

Does your site’s tab still show the host’s icon? This guide helps a site owner add a clear mark for the brand. Start with a real logo or approved photo that works at a small size.

**The path:** Approved mark → Site icon source → Served icon → Small-size check.

**Use this when:** a site has no appropriate icon, still shows a default, or changes its brand asset.

## Inputs
- A rights-cleared brand mark or appropriate real headshot and a square source file. For the source’s WordPress workflow, prepare a 512 by 512 pixel asset.
- The current icon-owning source and supported editing access for this platform or theme.
- Representative public pages and a fresh browser context for checking served declarations and visible tab behavior.

## First-run prompt

> Set the approved site icon through its actual owning source. Check small-size legibility, served icon declarations and fresh desktop/mobile behavior. Keep browser display and Google search eligibility separate.

## Steps
1. Inspect the currently served icon declarations and the CMS’s icon setting. Find which source controls them before adding another setting; different sizes and formats can be intentional rather than duplicates.
2. Choose a simple recognizable element from the approved brand asset. Crop it square and inspect it at roughly tab size. Do not use a busy wordmark or an invented face that ceases to be meaningful when small.
3. Prepare the source image for the actual platform’s requirements. A 512-pixel square is the source task’s WordPress preparation target; it is not a universal Google favicon requirement. Preserve the original and record the export.
4. Set the image in the installed WordPress version’s Site Icon control or the equivalent supported source on another platform. Confirm the actual menu for that version rather than assuming every theme exposes the old Customizer path.
5. Save and inspect ordinary public HTML. Resolve icon references relative to the page URL and check that the intended image loads. A valid CDN or custom file path is allowed; /favicon.ico is not mandatory.
6. Remove or correct a conflicting obsolete declaration at its owning source if it actually overrides the intended mark. Preserve legitimate alternate formats, device icons and app-specific assets.
7. Check the tab in fresh desktop and mobile contexts and inspect bookmark or home-screen appearance where included. Separate a stale browser cache from stale served HTML. Avoid changing a good asset repeatedly to chase a local cached icon.
8. Record the selected asset and source setting. Google has separate crawl and image eligibility rules and chooses when or whether to show the icon in search; a browser pass does not guarantee search-result display.

## Definition of done (QA checklist)

- [ ] The source is an approved brand asset, clear at small size.
- [ ] The active icon declarations resolve to the intended valid files.
- [ ] No obsolete conflicting source overrides the chosen icon.
- [ ] Desktop/mobile checks and any local caching limit are documented.
- [ ] Browser success is separated from search eligibility and unobserved Google display.

## Example(s)

**Fictional teaching example.** Oak Repair has a detailed logo with a long slogan. The lesson uses its approved oak-leaf mark alone in a square export. The site declares a 32-pixel icon and a larger touch icon from that source. Both are legitimate. A stale theme icon pointing to the old host is removed, and a fresh tab shows the leaf. No Google search-display result is claimed.
