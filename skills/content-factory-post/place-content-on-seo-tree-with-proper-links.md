# Place content on SEO Tree with proper links

A useful page can still be hard to find. This guide helps you connect it to the main topic and the next thing a reader needs. Start by finding the page that already owns that topic.

**The path:** Page’s purpose → Main topic owner → Useful links both ways → Checked map.

**Use this when:** A new or existing piece needs a clear place in the site’s topic map.

## Inputs
- The draft or existing canonical URL and its purpose: task guide, topic hub, story, or record of one run.
- The current [SEO Tree](https://blitzmetrics.com/seo-tree/) map and content inventory, with the agreed main page for each topic.
- The [Goals, Content, and Targeting](https://blitzmetrics.com/gct-business-strategy/) brief: the result wanted, the content used, and who it serves.
- Access and scope for the page and any related pages to be changed. Record an inbound-link handoff if another site owner must add it.

## First-run prompt

> Use my page, current site map, and authorized edit scope to find its real topic owner. Propose useful links in both directions, read the targets, and check named anchors. Make the already-authorized changes and verify them. Record any inbound edit another owner must make; do not invent a hub or claim a pending link is live.

## Steps
1. Read the piece and classify its role. A specific story or answer usually supports a broader guide; a guide may own a repeatable task. Do not mark a story definitive just because it has links.
2. Search the site inventory for an existing page that already answers the same main need. Enhance the canonical page when appropriate. Record why a distinct supporting page is needed rather than silently making a rival hub.
3. Choose the actual parent topic and any useful next guide. Read the target pages. Resolve each target to its final canonical URL; do not build new body links to a redirecting alias. A category or plugin suggestion is a clue, not proof of the right relationship.
4. Add a body link from the specific piece to its main topic or task guide where the reader needs the explanation. Use descriptive words that match the destination. Add related links only when they help a real next question.
5. Follow the [entity-linking guide](https://blitzmetrics.com/entity-linking/): use verified identity pages for people and managed brands, owned explainers for methods and tools, and precise primary sources when they substantiate a claim or needed action. Do not invent a person’s domain.
6. Add a relevant link from the parent or a suitable existing supporting page to the new piece within the authorized edit scope. Do not publish an inbound link from a live page to a private or unpublished target; stage that edit until target visibility is checked. If the edit is outside scope, give the responsible owner the exact sentence, target, and reason; keep inbound placement pending.
7. Save through the site’s supported source. Check each final destination and any fragment after #. Confirm the live body links when publication is in scope; draft links remain draft-only checks.
8. Update the inventory with this page’s role, primary parent, actual inbound source, links, and checked date. If no parent fits, state whether the content or map needs a decision rather than inventing a branch.

## Definition of done (QA checklist)

- [ ] The role and primary topic owner are stated and source-grounded.
- [ ] A useful upward body link reaches the final canonical URL for the correct main explanation.
- [ ] At least one real relevant inbound path is saved and verified, or its exact pending owner/action is stated; no live source exposes a private target.
- [ ] New links and named anchors reach the intended content; no unsupported duplicate hub or redirect alias was made.
- [ ] The inventory records the actual placement and verification state.

## Example(s)

**Fictional teaching example — no site was edited.** Maple Cycle has a main “Repair quotes” guide and a smaller story, “What happened when a photo missed the bent part.”

The story links up with “how our repair quotes work.” The guide links down with “a quote changed after inspection” beside the section explaining why photos are only a starting point. A booking page is linked where the reader is ready to arrange a visit.

The sample map is `Repair quotes guide ↔ inspection story → booking step`. It does not link every page to every other page. If the guide’s editor has not yet saved the inbound link, the story’s inventory row says “upward link checked; inbound edit pending,” not “fully connected.”

## When this runs

Run for each new page or a defined repair to an existing page. Repeat when the role, parent, or linked targets change. No automated site-wide link job is created.

## First-run setup and continuity

Use the exact account, source, destination and authority recorded for the job. Carry out publication, messages or repairs already authorized once their required checks pass; do not ask for the same approval again. If an action is outside that scope, finish the authorized work and state the specific remaining need. A login, plugin, or task file does not itself grant new authority.

Keep the latest state, record IDs, revisions and next owner in the project tracker or files. Before a retry, check the current saved/sent/published item to avoid duplicates or overwriting another edit. A model has no guaranteed memory, scheduler or account access just because it is called persistent. A future check needs a configured timer or a named person.

Keep all agent media previews muted with volume zero before playback. If this cannot be verified, use captions, metadata or still frames and state what was not tested. No first-load autoplay is part of these page instructions.
