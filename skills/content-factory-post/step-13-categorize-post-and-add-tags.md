# Step 13: Categorize post and add tags

Good labels help people find more useful work on your site. This guide helps you choose the right topic group and tags for a post. Start with the site’s own list, so you do not create two names for the same thing.

**The path:** Page purpose → Existing labels → Saved category and tags → Checked grouping.

**Use this when:** A WordPress post needs its category and tag labels set or corrected.

## Inputs
- The exact post, its [Goals, Content, and Targeting](https://blitzmetrics.com/gct-business-strategy/) brief and its place on the [SEO Tree](https://blitzmetrics.com/seo-tree/).
- The site’s current category/tag list and rules. A category groups related posts; a tag is a reusable label across posts.
- Permission to edit this post’s labels; scope for new terms if the existing list truly lacks a needed one.
- The content inventory, publication state, current canonical URL and permalink policy. Pages may not use post categories/tags unless the site explicitly adds that support.

## First-run prompt

> Use the exact post and current site taxonomy I provide. Select the right existing category and useful tags, save the authorized change, and verify the saved values. Keep draft and public archive checks separate. Do not create duplicate tags or add an internal stage system the site does not use.

## Steps
1. Read the post’s main purpose and current topic map. Identify the existing category that fits. A category archive and a maintained topic guide may be different pages; record both rather than assuming the category is the guide.
2. Open the post settings and Categories panel. Choose the agreed main category. Use a second only where the site policy and content support it. One primary category is a house choice; WordPress itself permits more than one.
3. Remove an accidental default “Uncategorized” assignment when a correct category is now set, within this post’s scope. Do not rename or delete the site’s global default category as part of a one-post task.
4. Open Tags and reuse exact existing terms. Choose only labels that help navigation or an established workflow. Stage tags, format tags, people and company names are not mandatory on every public site; do not invent them from an old template.
5. Review near-duplicates before creating a new tag. For example, “repair quotes” and “repair-quote” may point to the same idea. If the taxonomy needs a new term, follow the already-authorized taxonomy scope or record the specific missing decision.
6. Save the post in its intended state. Reopen its settings and confirm the actual assigned terms. Compare the canonical URL before and after because category-based permalink setups can change a public address; restore the scoped value or hold the result if the URL moved unexpectedly. If a machine lookup is part of the job, test the supported category/tag query with the correct IDs and access; do not assume every custom type exposes them.
7. For a published post, check its intended archive, visible labels and normal canonical URL. For a draft, inspect the archive’s existing siblings and the saved term assignment, but do not expect the unpublished post to appear publicly.
8. Update the inventory with the category/tag names or IDs, URL result and any justified not-applicable fields. Hand the record to [Configure search metadata](https://local-service-spotlight.github.io/task-library/?task=step-14a-configure-rankmath-seo-plugin#task-step-14a-configure-rankmath-seo-plugin).

## Definition of done (QA checklist)

- [ ] The category fits the post’s actual topic and the site’s current structure.
- [ ] Tags reuse useful existing terms; no duplicate or invented workflow taxonomy was added.
- [ ] Saved terms match the plan and the supported content type, with no unasked canonical URL change.
- [ ] Published archive behavior and canonical URL are checked only when applicable; draft status is not treated as an archive failure.
- [ ] The inventory records exact labels, URL state and any unresolved term decision.

## Example(s)

**Fictional teaching example — no taxonomy was edited.** Maple Cycle’s sample post answers “Can a photo get me a repair quote?” The site already uses category “Repair quotes” and tag “Planning a visit.”

The publisher selects those terms and rejects a new tag called “repair-quote” because it adds no useful distinction. The draft saves with both term IDs. It does not show in the public archive yet, which is expected for a draft.

After an authorized publish, the same archive should list it among related posts if that archive is part of the site’s design. No `Stage: Post` tag is created because this fictional public site has no such taxonomy.
